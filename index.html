System Architecture & Operational Topology

This section provides an architectural overview of GE Digital APM's Meta SQL abstraction layer. Meta SQL sits above native relational DBMS syntaxes (Oracle, Microsoft SQL Server, PostgreSQL), translating queries dynamically while enforcing platform-wide standards such as mandatory UTC temporal normalization and role-based security isolation.

Temporal Rule

UTC Date Standardization

All transactional dates and timestamps within GE Digital APM are stored strictly in Universal Coordinated Time (UTC).

Why it matters: Prevents synchronization errors across global IIoT sensors and regional EAM systems during time-series aggregation.
Now() & SysDate() calculate in UTC

Select Queries Overview

READ-ONLY

Select queries extract structured data from entity families. If duplicate field aliases occur, the Meta SQL engine appends sequential integers (e.g. Asset0, Asset1) to preserve 27-character namespace rules.

Meta SQL Syntax Example:
SELECT [MI_EQUIP000].[MI_EQUIP000_EQUIP_ID_C] "Equipment ID", 
       [MI_EQUIP000].[MI_EQUIP000_EQUIP_TECH_NBR_C] "Tech Number",
       [MI_FNCLOC00].[MI_FNCLOC00_FNC_LOC_C] "Functional Location"
FROM [MI_EQUIP000] 
JOIN_PRED [MI_FNCLOC00] ON {MIR_FLHSEQ}
Key Rule: Mathematical aggregations automatically force execution into unformatted mode.

Relational Join Mapping & Line Style Reference

In the GE APM graphical query designer, join types are visually denoted by line styles and arrows. In code, they map to explicit `JOIN_SUCC` or `JOIN_PRED` clauses over APM relationship families or manual equal joins.

Join Classification Database Execution Behavior UI Visual Indicator Meta SQL Clause Structure
APM Inner Join Only returns records actively linked via APM Relationship Family. ─────── (Solid Line) FROM [T1] JOIN_SUCC [T2] ON {Rel_Fam}
Manual Inner Join Matches records based on dynamic field equality across unrelated families. ─────── (Solid Line) FROM [T1] JOIN [T2] ON [T1].[F1] = [T2].[F2]
APM Outer Left Join Returns all predecessor records and matched successor records. ◄────── (Solid + Left Arrow) FROM [T1] LEFT JOIN SUCC [T2] ON {Rel_Fam}
Manual Outer Left Join Returns all Table #1 records and matching Table #2 records. - - - - - (Dashed Line) FROM [T1] LEFT JOIN [T2] ON [T1].[F1] = [T2].[F2]
APM Outer Right Join Returns all successor records regardless of predecessor linkage. ──────► (Solid + Right Arrow) FROM [T1] RIGHT JOIN SUCC [T2] ON {Rel_Fam}

Performance Optimization Workbench & Anti-Pattern Diagnostic

Evaluating Meta SQL query design against industrial database execution constraints. Inefficient joins, leading wildcards, or improper clause positioning introduce server-wide latency.

Sub-Optimal (Anti-Pattern) High Latency 
SELECT * FROM [Recommendation]
Optimized Architecture Fast Execution 
SELECT [REC_ID_C], [REC_DESC_TE] 
FROM [APM General Recommendation]
Architectural Evaluation:

Querying the root Recommendation family forces the DBMS to evaluate all polymorphic sub-families. Directing queries to explicit leaf families avoids unnecessary schema traversals.
